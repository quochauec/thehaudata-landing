Looker Studio Dashboards

Plan a dashboard around one audience, connect data in Looker Studio, build the page, and check it against a design checklist. Practice runs on the Global Electronics Retailer data and the class dashboard workbook.

A dashboard answers a few questions for one audience, fast. Looker Studio is Google's free tool for building one: connect data, place charts on a page, add filters. Plan a page in tab 3.

What Looker Studio

A free Google platform for data visualization, also called Google Data Studio. It blends several data sources into one report. It has 22+ native connectors and about 2,000 partner connectors.

Home screen Five places to know

  • Create starts a report or a new data source.
  • Reports and Data sources list what you already have.
  • Explorer lets you try a chart on a source without building a report.
  • Templates give you a starting layout.

Flow Context first, then build

  1. Context (step 0). Answer three questions before opening the tool: what is the objective of this dashboard, which data should it highlight, and who will use it.
  2. Connect. Create, then Data source. You can add, remove or change sources at any time.
  3. Build in the report view. Tabs for editing and adding charts, a window to change the selected chart, and the field list of your source. There are 17+ chart types.
  4. Add controls. A date range control filters the date field for a page or the whole report. A drop-down list filters a category.
  5. Theme and layout. Pick one of Google's themes or customise your own colours and fonts.
  6. Check the design. Run the seven-point checklist below before you share.

Checklist Seven points for a good dashboard

#PointWhat to doIn the Global Electronics data
1Know your dashboard typeDashboards differ by level of detail. DataCamp groups them as strategic, operational, analytical and tactical.A monthly revenue summary is strategic. A list of late deliveries is operational.
2Know your audienceExecutives want overall performance, this month against last month or last year, and a recommended action. Operations teams want order-level detail such as returns and order IDs. Ask how familiar they are with filters, and how often the data should refresh (quarterly to real time).The Head of Retail gets four scorecards. The delivery team gets an order table with filters.
3Design with a narrativePut parts in the order people should read them: headline numbers, then trend, then breakdown, then detail.Scorecards on top, revenue trend in the middle, country bars below.
4Guide with text and colourEmphasise what matters and mute the rest. Use one accent colour.Grey bars for all countries, orange for Online.
5Reduce cognitive loadFewer charts, consistent number formats, no decoration that carries no message.Twelve charts become three.
6Choose the layoutMatch the layout to the number of visuals and the space on the page.One page for the executive. A second page for operations, linked by a menu.
7Give context to complex visualsAnnotate, write titles that state the message, and note how a metric is defined."Average delivery days, online orders only."

Audience Executive or operations

The same data serves both, in different shapes. An executive page shows a few KPIs with a comparison period and ends with an action. An operations page shows detail and filters, and refreshes more often. Decide which one you are building before you add a chart.

Before Looker Prepare the data

Looker Studio draws what the source holds. If the metric you need is not in the file, such as revenue when the file has only quantity, add it in SQL, in the sheet, or through a data blend. The workbook for this lesson has no price column, which Practice 1 and Practice 4 come back to.

Watch out Mistakes in a first dashboard

  • Starting with charts. If you cannot say who reads the page and what they decide, every chart is a guess.
  • Counting rows as orders. The workbook has 62,884 rows but 26,326 orders, because an order has one row per product. Use Count Distinct on the order number.
  • A metric that ignores half the data. Delivery date exists only for online orders (13,165 lines). The average delivery time covers online orders, and the chart title should say so.
  • Partial periods. The data ends on 20 February 2021. A year-over-year card that includes it compares a full year with a few weeks.
  • Too many colours and charts. Each one asks the reader to work. An executive page that needs a legend lookup has failed point 5.
